# FHI SME Financial Health Prediction

This project trains a gradient-boosted ensemble to predict the Financial Health Index (FHI)
category of small and medium enterprises across four Southern African countries: Eswatini,
Lesotho, Zimbabwe and Malawi. The FHI is an ordinal three-class label (Low / Medium / High)
constructed from SME survey responses across four dimensions: savings and assets, debt and
repayment ability, resilience to shocks, and access to credit and financial services. The
dataset is from the [Zindi data.org Financial Health Prediction Challenge](https://zindi.africa/competitions/dataorg-financial-health-prediction-challenge),
comprising 9,618 training rows and 2,405 test rows collected via FinScope-style MSME surveys.

## Setup

**1. Clone the repository**

```bash
git clone https://github.com/your-username/fhi-sme-challenge.git
cd fhi-sme-challenge
```

**2. Create the conda environment**

```bash
conda env create -f environment.yml
conda activate fhi-sme
```

**3. Place the raw data files**

Download the competition data from the [Zindi challenge page](https://zindi.africa/competitions/dataorg-financial-health-prediction-challenge/data)
and place the three files in `data/raw/`:

```
data/raw/Train.csv
data/raw/Test.csv
data/raw/SampleSubmission.csv
```

## Running the Pipeline

**Full run (recommended)**

Runs all four steps in sequence: preprocessing, feature engineering, training, prediction.
Training takes approximately 25-30 minutes on a standard laptop CPU.

```bash
python pipeline.py
```

**Fast mode (sanity check)**

Passes `--fast` to the training step, which uses fewer estimators and a coarser
threshold grid. Completes in around 5-10 minutes. Do not submit results from fast mode.

```bash
python pipeline.py --fast
```

**Skip training, reuse existing artifacts**

If you already have `models/ordinal_artifacts.pkl` and only want to regenerate
the submission (for example after changing a threshold), skip the training step:

```bash
python pipeline.py --skip-train
```

**Run specific steps only**

Steps are numbered: 1=preprocess, 2=features, 3=train, 4=predict.

```bash
python pipeline.py --steps 1 2        # only preprocess and features
python pipeline.py --steps 3 4        # only train and predict (requires processed data)
python pipeline.py --steps 4          # only predict (requires artifacts and processed data)
```

**Run individual scripts**

Each script can also be run on its own from the project root:

```bash
python src/preprocess.py
python src/features.py
python src/ordinal_train.py           # full run
python src/ordinal_train.py --fast    # fast mode
python src/ordinal_predict.py
```

The generated submission CSV is saved to `submissions/` with the OOF score in the filename,
for example `submissions/submission_ordinal_oof0.8791.csv`.

## Key Decisions

| Decision | Reason |
|---|---|
| Weighted F1 as metric, not macro F1 | Weighted F1 weights each class by support, which is appropriate for the 65/30/5 class split. Macro F1 penalises the 470 High errors equally to the 6,280 Low errors, which is not what the competition scores. Confirmed via forum discussion. |
| Impute financial product NaN as 0 (Never had) | Product NaN rows consistently show lower High rates than rows where the respondent answered "Never had". Survey design supports this: an owner who has internet banking would answer the question. Silence implies absence. This was the single largest improvement: +0.04 OOF. |
| Do NOT impute future_risk_theft_stock and motivation_make_more_money NaN as 0 | These columns show a reversal: NaN rows have higher High rates than answered rows (7.6% vs 2.9%, 8.2% vs 2.2%). Imputing as 0 would destroy signal. |
| Ordinal binary decomposition instead of multiclass | Two binary models (P>=Medium, P==High) enforce the ordinal structure by construction and eliminate Low-to-High catastrophic errors. Gave +0.002 OOF over standard multiclass. |
| Joint country x target CV stratification | Ensures each fold preserves both country composition and class balance simultaneously. Without this, folds can have very different Lesotho proportions, destabilising the OOF estimate. |
| Within-country percentile ranks for monetary columns | Personal income and turnover are in local currency. Malawi Kwacha amounts are nominally much larger than Eswatini Lilangeni amounts for comparable businesses. Percentile ranks within each country make the values comparable without needing exchange rates. |
| NFKC unicode normalisation before any encoding | Perception and attitude columns contain multiple byte-level variants of "Don't know" from data collection corruption. Without normalisation these are treated as different categories. After normalisation the ensemble weight shifted from LGB=0.90/CAT=0.00 to LGB=0.40/CAT=0.50, indicating CatBoost benefited significantly from cleaner category strings. |
| Fold-safe target encoding inside CV | Target encoding computed on all rows before splitting would leak target information into the validation set. We fit the encoder only on training folds and transform validation folds separately each time. |
| Keep Lesotho in the global model rather than separating | Separating Lesotho into its own model and training on 1,944 rows with 6 High cases produced worse results (0.697 OOF for Lesotho) than the global model. The global model learns High patterns from 470 cases across all countries and transfers that signal to Lesotho through shared features. |

## Limitations

**Lesotho structural ceiling.** Lesotho uses a different survey instrument with 11 columns
entirely absent. With only 6 High cases in 1,944 rows (0.3% prevalence), the model
cannot learn meaningful High class signal for Lesotho. The OOF for Lesotho sits around
0.72 regardless of architecture. Since Lesotho is 20% of the data, this creates a hard
ceiling on the overall weighted F1.

**Reconstruction regime.** The target FHI was constructed from a subset of the same survey
variables used as features. The model is effectively reconstructing an index from its own
components rather than forecasting from independent signals. This explains why a simple
starter baseline scores above 0.85 with minimal effort, and why gains above 0.88 are
difficult to achieve.

**Non-reproducible peak performance.** The best submission (0.8895 public, 0.8829 private)
was generated from a training run that was not committed to version control before the
artifacts were overwritten. The reproducible pipeline baseline scores 0.8857 public
and 0.8852 private. Both use identical code; the difference is random seed variance
in gradient boosting.

**Single random seed.** All models use SEED=42. Gradient boosting with a single seed
can produce lucky or unlucky realisations. Multi-seed averaging (3-5 seeds) would reduce
variance but was not implemented before the competition closed.

**Ordinal integer encoding for nominal categoricals.** Categorical columns are encoded as
integers before being fed to LightGBM without specifying `categorical_feature`. This means
LightGBM uses numeric threshold splits on the arbitrary integer codes rather than the
optimal many-vs-many partition search available through native categorical handling.
Permutation importance on held-out folds showed near-zero importance for compliance and
attitude columns, likely because of this encoding choice.
